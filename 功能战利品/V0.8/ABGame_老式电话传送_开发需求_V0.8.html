接听形式 · 方案对比

目标：有老式电话的味道、战斗里不误触、所有特殊状态都能套用同一个动作。

A · 滑动接听

手机用户熟悉，但是智能机的感觉，和老式电话不搭；右手正在转镜头时容易被当成拖动，战斗中滑一段距离也慢。

B · 点按「摘听筒」

点一下听筒就弹起来，正是老式电话的动作。一下完成，和功能道具「只点按」规则一致；卡片整体都是热区，被控制、空中、濒死都用同一个动作。

C · 转拨盘

最复古，也最有趣，但要画圈，战斗中太慢；适合放在拨号方做纯动画，不适合接听。

D · 长按提起

可以防误触，但长按已经用来打开轮盘，会冲突；按住时被击飞还要重按，体验差。

推荐 B 的细节设计

来电卡

  • 位置：右侧道具槽上方、攻击键左上，不挡攻击 / 跳跃键；热区 ≥ 120×72pt。
  • 内容：会抖动的电话小怪 + 来电人头像和名字 + 「点我摘听筒」+ 倒计时条。
  • 挂断：左上角小 ✕（热区小，避免误点）；不想接也可以放着不管。
  • 情绪递进：剩 2s 时电话急得跳起来、吐舌头，铃声变快。

防误触

  • 卡片弹出后 0.25s 内的点按不算数（防止正好在连点攻击时点到）。
  • 点到卡片的那一下不会穿透到下面的按键。
  • 同一时间只显示一张来电；后来的电话排队，显示「+1」。
  • 手柄 / 键盘：映射到「交互键」（默认 F / 手柄 Y），与道具键分开。
好玩的补充：接通后，双方头顶短暂冒出电话线连接的气泡「喂？」「快来！」（可选，两条随机语音），队友之间有一种“在通话”的仪式感。

接听人特殊状态

规则核心：接听不判断接听人当前状态，任何状态都能接听。来电卡始终显示可点，倒计时照常走，不做置灰 / 隐藏 / 补时。

① 被控制（眩晕 / 击飞 / 抱住）

  • 来电卡照常弹出、照常可点，不置灰、不加状态图标。
  • 被控制期间也能接听，接听后正常进入传送读条。
  • 铃声照常；不因控制状态暂停倒计时或补时。

② 打开背包

  • 背包 / 地图等全屏界面也照常显示来电卡、照常可点。
  • 铃声正常播放；手机端加一下短震动。
  • 不因界面状态隐藏卡片、暂停倒计时或补时。

③ 跳起 / 掉落中

  • 可以在空中接听，读条在空中照常进行。
  • 读条中落地不打断；吞入时清掉下落速度，到达后站在地面，不算摔落伤害。
  • 如果正在掉出地图（掉出边界 / 坠入深渊），读条中断，按原规则处理掉落。

濒死状态 · 求救电话

濒死时武器和道具键都不能用，所以单独给一个「求救」键：只要背包里有老式电话（不用放在快捷槽），就会出现。

濒死界面：攻击键位置换成红色「求救」键

濒死者拨号

  • 位置：原攻击键位置（濒死时攻击键本来就不能用），红色大圆键 + 电话图标，呼吸闪动。
  • 点一下即拨号，自动选人：优先离自己最近的未濒死队友，濒死的队友不在名单里。
  • 拨号后求救键变成「等待中 ✕」，再点一下就挂断。
  • 对方接听后，对方传送到濒死者身边，直接救人。
  • 濒死流血倒计时不暂停；拨号期间可以继续爬行。

濒死者接听

  • 濒死者收到电话，同样点来电卡接听（V0.7 的“自动接听”取消，避免被动打乱）。
  • 传送后仍是濒死，落在呼叫人身边，由呼叫人救。
  • 呼叫人自己也濒死时，不能拨给濒死队友（两人都倒地没有意义）。

SOS 包装

  • 濒死求救的来电卡用红色 SOS 样式，铃声更急促（两短一长）。
  • 接听人小地图上出现呼叫人位置的红色电话标记，持续到通话结束。
  • 濒死求救也扣 1 次；没接通不扣。

传送落点 · 选点规则

在传送那一刻以呼叫人的位置为中心找点（呼叫人等待时一直在动，所以不用接听瞬间的位置）。

俯视图：候选点检查顺序与淘汰原因

候选点

  • 3 圈：1.2m / 2m / 3m；每圈 8 个方向，共 24 个点。
  • 顺序：先内圈后外圈；同一圈内按 后 → 左后 / 右后 → 左 / 右 → 左前 / 右前 → 前（不挡呼叫人的视线和射线）。
  • 选中第一个合格点；全部不合格进入兜底。

每个点要过 7 项检测

#检测判定
1可行走点在 NavMesh 可走区域上
2地面向下射线 1.5m 内有地面，坡度 ≤ 35°
3不悬空 / 不贴悬崖周围 0.6m 的 4 条下探射线都要打到地面
4不被挡角色胶囊体（半径 + 0.2m）不和墙、箱子、柜子、其他角色、怪物重叠
5同一侧呼叫人到落点之间没有墙（视线检测），且高度差 ≤ 0.8m
6不绕远NavMesh 路径长度 ≤ 直线距离 × 2（防止落到薄墙另一边）
7不危险不在陷阱、水、禁区、他人结界、撤离读条圈内

兜底与特殊情况

情况处理
24 个点都不合格（窄走廊、通风管、角落）改用呼叫人最近一次的安全落脚点再找一轮（每 0.5s 记录一次站在平地上的位置）
呼叫人在空中（跳起 / 掉落）以呼叫人正下方的地面为中心找点；下方 3m 内没地面，用最近安全落脚点
呼叫人在楼梯 / 斜坡只接受与呼叫人同一层（高度差 ≤ 0.8m）的点，不会落到楼下
呼叫人在门口、门正在关门的开关范围算作障碍
兜底也失败传送取消，双方提示「这里信号不好」，CD 不退
两次检测：接听那一刻先预检一次（不合格就提前提示呼叫人“换个地方”），传送那一刻再正式检测并锁定落点；落点由服务器计算，客户端只表现。

到达后

  • 朝向与呼叫人一致，镜头不翻转。
  • 0.5s 落地保护：不会被控制，防止被人守着落点整蛊。
  • 吐出烟尘和「噗」声所有人都能看到、听到，对手也能借此发现你们。

通用规则

  • 拨号对象只能是队友；单排没有队友时电话槽变灰（V0.7 的“拨给教导主任”放到待确认）。
  • 自动选人：正常时优先濒死队友，其次距离最远的队友；濒死时优先最近的未濒死队友。
  • 同一个人同时只能接一个电话，后来的排队。
  • 失败不退还 CD：点按瞬间即进 60s CD。
  • 铃声是 3D 声源，接听人周围 15m 都能听到；对手能循声找人。

反制

  • 听到铃声，过去推一下 / 用泡泡困住，就能打断读条。
  • 守在呼叫人旁边，等“噗”出来的队友（但有 0.5s 落地保护）。

程序要点

通话状态机（点击放大）

需要的接口

  • 队友可接通判断（在线、未淘汰、未撤离、非濒死互拨）
  • 通话会话：呼叫人、接听人、品质、开始时间、窗口时长、状态
  • 接听不做状态查询：来电卡常显可点，无需判断被控 / 背包 / 濒死
  • 不做状态事件监听：来电卡常显可点，倒计时不暂停、不补时
  • 落点搜索：NavMesh 采样 + 射线 + 胶囊体重叠 + 危险区查询
  • 最近安全落脚点缓存（每 0.5s）
  • 传送：清速度、设朝向、0.5s 落地保护 Buff

同步

  • 服务器负责状态机、计时和落点，客户端只播动画和 UI。
  • 来电卡倒计时以服务器时间为准，背包关闭后按剩余时间显示。
  • 接听请求带上通话 ID，过期或重复请求忽略。
  • 读条打断由服务器的控制事件触发。
